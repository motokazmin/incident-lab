# incident-lab

Браузерный полигон инцидентов для бэкенд-инженеров: живой сервис под нагрузкой с настоящей поломкой, настоящие
инструменты, проверка починки по поведению системы, разбор после решения. Запуск сразу в браузере, без установки у пользователя.

Карта — [docs/architecture.md](docs/architecture.md), состояние — [docs/state.md](docs/state.md), решения — [docs/adr/](docs/adr/), план — [docs/plan.md](docs/plan.md), каталог сценариев — [docs/scenarios.md](docs/scenarios.md).

## Команды

- `scripts/setup-firecracker.sh` — скачать Firecracker и гостевое ядро в `.data/fc` со сверкой контрольной суммы.
- `scripts/build-images.sh [id ...]` — собрать агент, образы и диски в `.data/images`; без аргументов все сюжеты, неизменившийся диск не пересобирается. Нужен Docker.
- `go test ./...` — быстрые тесты. `go test -tags e2e ./platform/internal/lab/ -parallel 1 -timeout 3h` — настоящие виртуалки по одной, как у пользователя, нужен `/dev/kvm`. Обычно достаточно сюжета в работе: `-run TestScenario/<id>`; все сюжеты — при изменении каркаса.
- `scripts/run.sh [--build]` — остановить прежний сервер со всеми стендами, подготовить недостающее и запустить новый на http://127.0.0.1:8090; с `--build` пересобрать образы и веб.
- `(cd web && npm ci && npm run build)`, затем `go run ./platform/cmd/server` — http://127.0.0.1:8090.

## Запреты

- **Чужой код никогда не запускается на сервере с другими сервисами и секретами.** См. [ADR 0002](docs/adr/0002-untrusted-code-boundary.md).

| имя | роль | модель | когда зовём |
|---|---|---|---|
| `sandbox-reviewer` | Ищет обходы изоляции, утечки и ошибки в выводах о безопасности | opus | Перед решением об изоляции и перед открытым запуском |
| `scenario-architect` | Цена добавления сюжета, граница каркаса и сценария | opus | Перед новым классом сюжетов и при изменении каркаса |

Добавлять роли по мере задач.

## На ревью проверять

Заготовка, пополнять.

- **Граница доверия:** всё, что исходит из песочницы (результат проверки, логи, события), считается данными злоумышленника. Каркас не принимает оттуда решений без проверки на своей стороне.
- **Песочница не получает секретов** и маршрута к управляющей части, кроме явно разрешённого канала.
- **Лимиты задаёт каркас:** CPU, память, диск, время, сеть. Сценарий их ослабить не может.
- **Сценарий детерминирован:** при том же сиде поломка и нагрузка воспроизводятся. Проверка починки не должна зависеть от удачи.
- **Запрещённая починка распознаётся по поведению системы, а не по разбору кода пользователя.**

## Правила из работы

- **Отметка в логе — не доказательство успеха: сверяй результат самой операции.** Разведка записала «PostgreSQL стартует 5 с», хотя это был таймаут DNS и падение; 05.11.
- **Шум проверки разбирай до нуля, а не прячь порогом.** 0,7% ошибок на верной починке оказались рестартом; настоящая починка даёт 0,0%, поэтому порог 0,5% не маскирует сбои; 05.11.
- **`svc` возвращает управление только после ответа сервиса.** Иначе проверка стартует в окно рестарта и ложно проваливается; 05.11.
- **В PID 1 гостя агент запускается не через `&`.** Фоновая задача неинтерактивного `sh` игнорирует SIGINT, игнорирование наследуется через `exec`, и в терминале стенда Ctrl+C не останавливал `svc logs`. Держит `TestTerminalSignals`; 05.11.

- **Подсказку при провале вешай на признак в системе, а не на проверку, где случился провал.** Большой пул даёт ровно 0,5% ошибок, провал прыгал между двумя проверками, и подсказка появлялась через раз. Нашёл базовый прогон; 05.11.
- **Каждый запуск платформы получает свой `RunDir`.** `firecracker.New` чистит его целиком, и e2e с общим каталогом удалял бы диски живых стендов сервера; 05.11.

- **Действие, которое читает состояние сервиса, обязано пережить окно рестарта: процесса нет, а завершающийся уже вне cgroup.** `memory-limit` в окне давал «вне cgroup», и ложная починка «перезапуск по расписанию» получала чужую подсказку примерно в 5% проверок. Держит `TestServiceCgroup`; 07.11.
