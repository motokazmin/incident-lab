# План: браузерный полигон инцидентов

Черновик от 05.11. Статус поставок — в [state.md](state.md): 0–2 готовы локально, 3–4 частично.

## Цель первой версии

Инженер открывает ссылку, ничего не ставит и за час проходит один настоящий инцидент.

**Готово, когда:** 20 незнакомых инженеров запустили сценарий в браузере, хотя бы часть дошла до конца, и стенд ни разу не утёк за пределы песочницы. Цифра условная, уточнить с пользователем.

## Устройство

```text
Браузер ──HTTPS──> Шлюз ──vsock──> Агент в песочнице
   │                 │               ├─ учебный сервис (Go)
   │                 │               ├─ PostgreSQL, Redis
   │                 │               ├─ нагрузка, логи, метрики
   ▼                 ▼               └─ терминал пользователя
 Веб, API        Проверяющий (вне песочницы)
```

- Один пользователь — одна микро-виртуалка Firecracker. Внутри весь стенд.
- Исходящей сети в песочнице нет. Связь только через vsock с агентом.
- В браузере терминал (xterm.js), редактор (Monaco), графики.
- Состояние песочницы одноразовое. После сеанса она уничтожается и не используется повторно.
- Быстрый старт — прогретый пул. Снимки как ускорение рассматриваем отдельно: восстановление одного снимка в несколько машин небезопасно без мер защиты (одинаковая энтропия).

## Изоляция

Выбор: Firecracker с jailer и seccomp, так как код пользователя считаем враждебным. gVisor — запасной вариант, если у дешёвого сервера нет KVM, но защищает слабее, и ADR об этом принимается отдельно.

Обязательное условие выбора сервера: рабочий `/dev/kvm` на голом железе. Вложенная виртуализация — только для закрытого теста: SMT, микрокод и соседей там контролирует не хозяин стенда. Проверить до оплаты.

## Модель угроз (минимум)

| Угроза | Мера |
|---|---|
| Выход из виртуалки | Firecracker + jailer, обновления, одноразовый сервер без секретов |
| Майнинг, атаки наружу | Нет исходящей сети, лимиты CPU и времени |
| Захват браузера через контент из песочницы | Графики и всё, что отдаёт песочница, только с отдельного домена без cookie основного сайта |
| Подделка результата | Проверка — обратная связь, а не доказательство (ADR 0004). Рейтинг и сертификаты только после выноса системы из-под власти пользователя |
| Исчерпание ресурсов | Лимит стендов на пользователя, очередь, таймаут простоя |
| Доступ к управляющей части | Песочница видит только агентский протокол, база и секреты вне сервера стендов |

## Текущий курс

Решение пользователя 05.11: пока делаем тренажёры локально, около пяти сценариев. Поставки 3, 5 и 6 (несколько пользователей, закрытый тест, открытый запуск) отложены до возвращения к работе через сайт. Вход, метрика успеха, аудитория и условия ADR 0003 тоже ждут этого момента. Запрет запускать чужой код на этой машине остаётся в силе.

Все возможные сценарии — в [scenarios.md](scenarios.md). Выбор из каталога не меняет сам каталог.

## Поставки

0. **Разведка на локальной машине.** Firecracker запускает образ с PostgreSQL и сервисом. Замерить время старта, память и сколько стендов выдерживают 8 ядер и 15 ГБ. Готово: таблица замеров в `docs/reviews/`, решение об изоляции принято.
1. **Один стенд, один сценарий.** Браузер → шлюз → терминал и редактор внутри песочницы, сценарий «кончился пул соединений». Готово: сценарий проходится от алерта до починки на локальной машине.
2. **Проверка починки.** Проверяющий, тест повышенной нагрузкой, отличие настоящей починки от рестарта. Готово: автотесты на верную починку, рестарт и заглушку.
3. **Несколько пользователей.** Пул, очередь, лимиты, таймауты. Готово: нагрузочный тест без утечек ресурсов, 10 одновременных стендов либо честный предел из замеров.
4. **Разбор.** Лента действий, сравнение с эталонным путём.
5. **Закрытый тест** с доверенными людьми на отдельной временной машине по ADR 0002 и условиям ADR 0003. Туннель на локальную машину запрещён.
6. **Открытый запуск** на отдельном сервере по ADR 0002, после внешней проверки безопасности `sandbox-reviewer`.
