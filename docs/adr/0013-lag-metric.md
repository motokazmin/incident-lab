# 0013. Отставание фоновой работы — метрика действием сюжета

**Контекст.** Сюжет №60 «Письма о заказах опаздывают»: обработчики очереди задач в PostgreSQL встают друг за другом на `FOR UPDATE`, писем уходит 6,5 в секунду при любом числе обработчиков (замер 11.11, [разбор](../reviews/2026-11-11-queue-skip-locked.md)). Сайт при этом отвечает быстро и без ошибок, а алерт каркаса видел только долю ошибок и p95 HTTP снаружи. Такой же асинхронный симптом у №15, 21, 35, 49, 52 каталога.

Рассмотрены:
- **Зонд снаружи** (`scenario-architect`): каркас создаёт пробный заказ и ждёт «письмо отправлено» через HTTP сервиса. Время меряет хост, но готовность читается из кода пользователя: заглушка или удаление задач обманут зонд. Около 250 строк: цикл ожидания, возраст операции в полёте.
- **Число с ручки сервиса:** дешевле всего, но число сообщает тот же код, что чинит пользователь, и потерю сообщений (№35, 52) сервис не видит.
- **503 при переполнении очереди:** без каркаса, но симптом выдуман и ломает урок «ошибок нет, а люди ждут».

**Решение** (пользователь, 11.11): метрика действием сюжета. `Scenario.Lag {Action, Title}` и порог `Alert.MaxLag`.

- Пока идёт нагрузка, каркас раз в 2 с вызывает `Action` сюжета, опросы идут по одному, каждый не дольше 3 с. Опрос останавливается вместе с нагрузкой, поэтому во время проверки его нет.
- Действие печатает одно число — секунды. Каркас принимает только конечное число от 0 до 24 ч, остальное пропускает.
- Замер пишется в посекундную корзину `Recorder` полем `LagMs` и запросом не считается: график ошибок и доля ошибок не меняются.
- Порог — нижняя медиана замеров за окно алерта, и замеров в окне не меньше трёх: один выброс алерт не поднимает, в том числе в первые секунды нагрузки и при чётном числе замеров. Замер помечается временем начала опроса, а не ответа. Порог отставания проверяется раньше выхода «запросов не было».
- Третий график появляется только у сюжета с `Lag`, подпись — `Lag.Title`.
- Для №60 действие сверяет заказы с журналом почтового шлюза вне `/srv/app`, а не с таблицей задач: так видно и вставшую очередь, и заглушку вместо отправки.

**Последствия.** Цена — два поля контракта, около 60 строк в `lab` и `load`, необязательная серия в вебе; `TestAlertReason`, `TestParseLag`, `TestPollLag`, `TestLagIsNotARequest`, проверка `Lag` в `scenarios_test`. Метрика приходит из песочницы, где пользователь root, поэтому годится для алерта и графика, но не для вердикта: проверка починки судит по своим замерам (ADR 0004). Действие стартует процесс в госте каждые 2 с — дёшево для `psql` с индексом, сюжету с тяжёлым замером нужен свой период. Зонд снаружи остаётся вариантом, если появится сюжет, где готовность можно проверить только с хоста.
