## Что понял за сессию
- busybox `kill -l N` для незнакомого номера печатает сам номер, а не пустоту и не ошибку: код 200 выглядел бы как «сигнал 72». Сигналов в Linux 64, поэтому сигнал — только код 129–192.
- Процесс, который завершается, уже вышел из `cgroup.procs`, но ещё виден в `/proc` и `pidof`. Сверка «каждый процесс в cgroup» при частых рестартах давала «вне cgroup» в 2 из 150 чтений даже после ожидания процесса; лечится повтором через 0,1 с. Держит `TestServiceCgroup`.
- `/debug/pprof/` и `/debug/pprof/?debug=1` — HTML, в терминале нечитаемы; профили с `?debug=1` читаются. В брифинге адрес без `curl` пользователь ввёл как команду.
- У `memory.max` ядро может не убивать, а пробуксовывать: вытесняет и подчитывает с диска страницы кода сервиса, `max` в `memory.events` растёт, `oom` = 0, запросы по 8–12 с. Замер на простой программе этого не показал: там почти не исполнялся код. Лечение — бинарник в tmpfs (`lab-service-run`), см. ADR 0007.
- Подсказки при провале проверяются в e2e подстрокой: «перезапускался» совпадало и с «не перезапускался». Метка должна быть уникальной для одной подсказки.
- Счёт горутин «до и после» шумит от keep-alive и брошенных вызовов; счёт только горутин с кадром `main.*` после паузы даёт ровно 0 на верной починке, допуск 3.
- Проверки `keeps-restarting` ходят по товарам 201–5000, фон — по 1–200: иначе кэш поверх утечки проходил бы.
- 06.11 терминал в браузере один раз показался двойным и прошёл сам. В DOM был один `.xterm`, виртуалка одна, причина не найдена. Повторится — смотреть, менялся ли размер окна.
- e2e гоняем по одной виртуалке (`-parallel 1`), как работает пользователь; при новом сюжете только его, все сюжеты только при правке каркаса. Шум параллельного прогона двигал p95 индекса по дате от 63 до 485 мс.
- Путь к сокету Firecracker длиннее 108 символов: стенд виснет на старте и падает по таймауту 90 с. Каталог `-data` не класть в scratchpad.
- На порту 8090 жил сервер прошлой сессии со старым списком сюжетов. Второй экземпляр запускать с другим `-addr` и `-data`.
- Импорт в госте отвергнут разбором, см. [ADR 0006](adr/0006-traffic-reveals-the-fault.md): таблица в образе, сбой вскрывает `Scenario.Rise`.
- Общий пакет `platform/scenario/checks` не завели: второй сюжет почти не дублирует первый, вынесение было бы ради одной строки. Вернуться на третьем сюжете.

- Ctrl+C в терминале стенда: SIGINT наследовался как игнорируемый от `&` в `lab-init`. Go сохраняет игнорирование только SIGINT и SIGHUP, поэтому Ctrl+\ работал и след путал. Проверять маску: `grep SigIgn /proc/self/status`.

- `docker export` даёт пустой `/etc/hosts`, поэтому его пишет `lab-init`. tmpfs на `/run` стирает каталоги образа.
- `FOR UPDATE` в сценарии усиливает утечку: следующий заказ ждёт блокировку и тоже держит соединение. Первые 503 видны за минуту до алерта, это задумано.

- Большие таблицы: PostgreSQL открывает файлы таблиц на запись даже для SELECT, overlay копирует их на диск стенда целиком. Диск 1024 МиБ, для сюжета с индексом держать таблицу около 300 МБ.
