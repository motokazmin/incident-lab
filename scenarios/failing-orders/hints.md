## Что говорят графики

Ошибки начались вместе с распродажей и идут волнами: всплеск после каждой рассылки, между ними тихо. Сервис не перезапускается и не лежит: сбой случается, когда много запросов приходят разом.

## Что в логах

Выполни `svc logs` и останови его через Ctrl+C. Найди красные строки: в какой функции ошибка и что она говорит?

## Что пишет база

Ошибку сервису вернула база. Её журнал подробнее:

```
grep -A9 'deadlock detected' /var/log/postgresql.log | tail -n 30
```

Кто кого ждёт и на каких запросах?

## Сколько их

База считает такие случаи сама. Выполни запрос несколько раз подряд:

```
psql -U postgres -d shop -c "select deadlocks from pg_stat_database where datname='shop'"
```

## Какие товары

Журнал называет товар, на котором оборвалась транзакция: в строке `CONTEXT` у неё есть `parameters`, где `$2` — номер товара. Тот же номер стоит в `svc logs` после слова «товар». Какие товары берут два заказа, видно только из самих заказов. Сравни два заказа из истории с двумя общими товарами:

```
curl localhost:8080/orders/1; echo; curl localhost:8080/orders/5
```

## Где порядок

Повтор заказа берёт позиции в порядке, в каком их добавлял покупатель (`orderItems`, `ORDER BY position`), а `placeOrder` в `orders.go` блокирует товары по одному в этом же порядке. У заказов 1 и 5 он встречный: каждый держит свой первый товар и ждёт товар другого. Порядок приходит из двух мест: из истории заказа и из тела `POST /orders`. Подумай, где его выправить для обоих.

## Готовая правка

Блокируй товары всегда в одном порядке. В начале `placeOrder` отсортируй копию позиций по `product_id`:

```go
items = slices.Clone(items)
slices.SortFunc(items, func(a, b item) int { return a.ProductID - b.ProductID })
```

Добавь `"slices"` в импорт, сохрани файл, выполни `svc deploy` и нажми «Проверить починку».
